# Linux / NAS 网页版开发计划

范围：新建媒体库、单实例、可信用户；身份验证由反向代理提供。不迁移 Windows 数据，不增加转码或多用户权限系统。保留现有 Electron 用法。

## 阶段与提交

1. **计划与 fork**：记录范围、接口约定和验证策略，在个人 GitHub fork 开发。
2. **Linux 路径与扫描可靠性**：修复 POSIX 根路径、大小写身份和索引目录查找；不完整扫描不得清除未读目录的索引。添加针对性回归测试。
3. **网页与子路径部署**：`BASE_PATH=/luna`（默认空）作为唯一外部 URL 前缀。反代保留前缀，应用负责路由挂载；静态资源、API、封面、音视频、下载都遵循前缀。网页模式使用服务器目录输入/浏览及图片上传，隐藏桌面专属入口。根路径和子路径都进行 HTTP 与浏览器验证。
4. **容器与发布**：Node 生产依赖镜像，`/data`、`/cache`、`/media` 分离；Compose 与反代示例；GitHub Actions 测试并构建 linux/amd64、linux/arm64 镜像，发布 GHCR。默认分支发布 latest，版本标签发布对应版本，允许手动触发。
5. **集成验证与交付**：验证新库扫描、播放 Range、封面/歌词、ZIP、数据持久化、子路径和镜像构建；修复发现的问题并逐阶段提交，推送 fork，检查 Actions 发布结果。

## 部署约定

- `HOST=0.0.0.0`、`PORT=8787`、`LAM_DATA_DIR=/data`、`LAM_CACHE_DIR=/cache`。
- 数据库位于 NAS 本机存储卷，单容器持有 SQLite 数据库。
- 浏览器输入的是容器路径，例如 `/media/music`，不是客户端目录。
- 默认媒体只读；可显式挂载读写以使用音频标签写回。数据库内收藏、标签等不受只读媒体影响。
- 不提供内置认证；访问边界由部署者反向代理配置。
- 不打包用户数据或外部 DLsite 数据库；索引可单独挂载。

## 验证策略

执行修改涉及的路径、扫描、数据库与网页部署测试，使用临时数据和合成媒体，不修改真实媒体。容器优先本地验证，若本机运行时受限则使用 Actions 验证，并明确记录没有实测的项目。任何需要外部授权而暂时无法完成的步骤记录真实状态，不将配置文件等同于发布成功。
